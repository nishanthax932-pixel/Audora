# Audora 20-point product and infrastructure audit
**Audit date:** 2026-11-09  
**Scope:** Default branch source, README, user guide, release checklist, server, browser client, image client, package scripts, and existing PR changes.  
**Important:** This is a source/configuration audit. It is not a live deployment, real-model, browser, or Android-device test.

## Executive finding
Audora has a real Express API gateway and a browser chat workspace, but the default configuration expects a separately hosted OpenAI-compatible inference endpoint at `127.0.0.1:8000`. The repository does not contain model weights or a hosted inference endpoint. With no configured external model server and credentials, chat correctly returns a setup error. A phone-only owner therefore needs hosted inference; the phone itself should remain the client/development device.

## Status key
- **Present:** implemented in source and documented.
- **Partial:** a limited path exists, but needs external configuration, has important constraints, or is not production-complete.
- **Missing:** no implementation found in the audited source.
- **Unverified:** source/configuration exists, but live end-to-end behavior was not tested.

## Existing pull requests to keep separate

- PR #18: responsive workspace UI refresh.
These are separate proposals. This audit does not merge either PR or assume their changes are deployed.

## Phone-only hosting recommendation
1. Keep GitHub as source control and deployment trigger.
2. Keep the existing browser/Android client.
3. Evaluate Cloudflare Workers as a secure API gateway and Workers AI as the first hosted inference candidate; confirm model availability, account eligibility, quotas, streaming support, and compatibility before committing to it.
4. Evaluate D1 for durable history only after authentication and data-deletion design.
5. Keep image generation and voice as separate optional services; do not promise unlimited free usage.
6. Store all provider credentials as server-side secrets. Never embed secrets in the Android app or browser JavaScript.

## Acceptance rule
A feature is marked complete only after its real end-to-end path is tested. Mocked tests and a green CI run do not prove model quality, hosted inference, image generation, or deployment availability. No paid provider, billing key, or third-party fallback is enabled by this audit.
